## Implemented architecture

`CameraAdapter` protocol separates connection/capabilities, live-view frames, shutter command reference and captured file retrieval. Typed capabilities/preview/captured-photo models and staged CameraError distinguish demo, physical shutter, original file and uncertainty. Vendor placeholder refuses unsupported operations; it never falls back to preview images. Optional UVC adapter is isolated and explicitly frame-based DEMO, imports OpenCV only after explicit connect. No new dependency is needed for Mock.

CameraController runs on laptop with an OS process lease, one session lease and a non-overlapping capture lock. Run one Uvicorn worker for camera use; another process cannot take the camera. Owner Bearer is required for session camera commands/status/frame/native file. Host-only cookie+CSRF APIs configure adapters/guest access/disconnect; failure injection only for development Mock when CAMERA_ALLOW_FAULTS=true. CAMERA_GUEST_ENABLED defaults false and Host can arm it; local helper explicitly enables Mock for testing. Existing public session creation is not kiosk enrollment—restrict deployment to the trusted booth network until station provisioning/public routing are finalized.

Live View uses authenticated same-origin JPEG frame polling (~5fps nominal) instead of a long-lived MJPEG response. Browser decodes each blob before displaying; sequence and request timeout catch frozen/network frames, a watchdog hides stale images, server checks source timestamp age. Client clock is not compared with host clock. Busy capture/transfer is labeled as a pause rather than a healthy video feed. Reconnect can recover without discarding photos. Resource release: stop frame polling/revoke blobs/abort request at navigation/pagehide, send owner disconnect; TTL monitor disconnects abandoned leases after 30s default. In-flight capture is allowed to finish safely; disconnect cannot interrupt it.

Countdown and retake reuse the existing frontend timer/slot/session modules. Host capture sends only slot_index + idempotency key; no preview pixels. Backend journals capturing → transferring → captured, obtains file through adapter, validates byte/pixel/MIME limits, stores **exact native bytes/hash** in camera_originals, and stores normalized EXIF-aware PNG in existing photos/slots. Session progress advances only after persisted ACK and saved-image decode. The display canvas is built from the saved photo endpoint, never liveVideo/simLiveCanvas/hostCameraPreview. All editor/filter/composite algorithms remain unchanged.

Capture idempotency survives restart. A lost capture ACK or failed image display retries the same key/file, not another shot. Transfer failure retries the same adapter reference/native file without shutter. Safe pre-transfer failures allow a new key only after explicit retry; interrupted/uncertain shutter remains blocked for Host investigation. Concurrent shot commands return busy; revision check rejects overwriting a slot changed during transfer and retains native file. Errors do not increment the counter or remove old retake photos.

Migration 005 rebuilds photos with an additional camera_original source using create/copy/drop/rename, preserves IDs/files/slots, and adds camera_captures. Foreign keys are disabled outside migration transaction only, checked before commit and re-enabled. Existing upload API still accepts only legacy demo/webcam_frame/manual_upload; callers cannot claim camera-original provenance by uploading a browser screenshot. Unfinished shutter journals become failed/uncertain after process ownership is reacquired; interrupted transfers can retry their durable reference/file.

Capture Mode adds an in-page viewport overlay with object-contain preview, large countdown/progress and stop/review control; no native Fullscreen dependency. Existing header/sidebar/setup are covered/hidden during capture and restored on review/Result. Event heading AMAZING RACE 2026 added. The polished 75/25 Setup layout is intentionally deferred to Phase 6 per request.

## Manual laptop / iPad test

1. Root terminal: `python scripts/run_local_backend.py --admin`. Pick your own credentials (12+ character password). Helper explicitly forces host Mock + Mock Printer, enables guest camera and localhost QR. No real shutter, no paper, no public tunnel.
2. Second terminal: `cd frontend`, `npm.cmd ci`, `npm.cmd run dev:host`. Open http://localhost:5173. `npm.cmd run dev` retains legacy browser-demo default, with Host Camera available in camera selector.
3. Select 4/6 layout/timer and Start; preview fills viewport, countdown sends backend captures, progress advances after saved files. Stop/review and retake a slot; other slots stay unchanged. Go Result, customize, Confirm/Create QR, guest download and Mock print. `/admin` shows camera name/capabilities/errors plus existing gallery/queue/reprint/logout.
4. For an actual iPad on the same trusted test LAN, run Vite explicitly with `npm.cmd run dev:host -- --host 0.0.0.0`, then open `http://<laptop-LAN-IP>:5173` on iPad. Backend may remain loopback because Vite proxies same-origin `/api` and `/p` to laptop. Use the actual Windows IPv4 address; localhost on iPad would mean iPad. Windows firewall/network isolation may require operator configuration; nothing is opened automatically. Prefer trusted HTTPS for actual operation and do not expose Host credentials on an untrusted network. No actual iPad/LAN validation claimed.
5. QR from helper still points to laptop localhost and **cannot be used on another phone/iPad**; booth preview/capture via LAN is separate from public Guest URL. Public HTTPS/DNS/tunnel is not deployed in this phase.

Build host artifact: `npm.cmd run build:host` (dist-host). Standard production build keeps browser demo disabled; host mode opts into backend-camera path and reports actual adapter capabilities. Building either artifact does not make hardware ready. Configure supported real adapter only after hardware verification.

ENV defaults: CAMERA_ADAPTER=mock; CAMERA_GUEST_ENABLED=false; CAMERA_DEVICE_INDEX=0; CAMERA_TIMEOUT_SECONDS=15; CAMERA_LEASE_SECONDS=30; CAMERA_STALE_SECONDS=3; CAMERA_ALLOW_FAULTS=false. Host adapter choice is runtime-only and resets to ENV on restart; guest arming persists in host_settings. No secrets in frontend/.env.host (only VITE_CAMERA_SOURCE=host).

For HTTP LAN testing on browsers without crypto.randomUUID, ID creation uses a UUIDv4 helper backed by crypto.getRandomValues; it refuses when secure randomness is unavailable. No Math.random or plaintext fixed credentials fallback. [MDN Crypto](https://developer.mozilla.org/en-US/docs/Web/API/Crypto) documents the secure-context difference. Built-host E2E removes randomUUID to test the fallback. Device changes are blocked while a capture is pending; choosing a layout before any shot releases the old preview session before starting the correctly configured one.

## Limits / hardware-dependent tasks / Phase 6 requirements

SOFTWARE READY requires the final Mock-based suites/builds below to pass. HARDWARE READY additionally requires verified real shutter, original file transfer and remote Live View on the exact camera; none has been performed. Physical webcam, DSLR, printer, phone QR, Safari/iPad device, actual network latency/DPI/paper remain NOT TESTED. Vendor SDK remains BLOCKED BY HARDWARE; CUPS and native MediaCapture bridge are NOT IMPLEMENTED.

Timeouts are enforced by Mock and the adapter deadline contract. UVC demo checks deadlines around native calls; a driver hung inside read cannot be forcibly cancelled and may need host restart. A future vendor integration must isolate such calls and retain exclusive capture ownership until outcome is known. Do not automatically retry uncertain physical shutter. Native photo records are private; retention/recovery UI for orphaned captures is not implemented. Existing frontend does not restore the entire editor session after page reload; Host still sees persisted files/sessions.

Before Phase 6: identify camera/model/firmware/SDK and perform device acceptance (see matrix); verify printer/paper/crop/DPI/QR on physical output; finalize 75/25 Setup and landscape Safari ergonomics, network/proxy/HTTPS and stable public Guest origin, kiosk enrollment/routing (no public camera control), consistent backup/retention/restore, event runbook/monitoring/restart and on-device failure acceptance. Phase 6 is not started here.

Verification labels: PASS — tested Mock/software features above; FAIL — no unresolved reproducible core failure after fixes; NOT TESTED — physical camera/webcam/printer/phone/Safari/network conditions listed above; NOT IMPLEMENTED/BLOCKED BY HARDWARE — real vendor SDK/shutter integration, hardware-specific recovery and original RAW codec pipeline. The optional UVC adapter exposes successful driver reads, not proof that the physical sensor is updating; sensor-level freshness/latency must be checked on actual hardware.
